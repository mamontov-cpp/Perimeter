# Редактор карт Perimeter (`map_editor`)

Отдельное Qt-приложение для редактирования миров и боевых карт Perimeter.
Исходники — `Source/MapEditor/`; исходники игры (Terra, tx3d, Game, Util…)
не изменяются. Технические решения и находки: `docs/architecture.md`,
`docs/context.md`; план — `docs/map_editor_plan.md`.

## Сборка

Требуется: CMake ≥ 3.24, Qt 6 (Widgets; Qt5 принимается с предупреждением),
MSVC 2022+ (или совместимый компилятор; игра собирается VS 2022).

```bat
cmake -S . -B build -G "Visual Studio 18 2026" ^
      -DOPTION_MAP_EDITOR=ON ^
      -DMAP_EDITOR_QT_PREFIX=D:/SDKs/Qt/6.12.0/msvc2022_64
cmake --build build --config Release --target map_editor -- -m
```

- `OPTION_MAP_EDITOR` (по умолчанию OFF) — игровая сборка не меняется.
- `MAP_EDITOR_QT_PREFIX` — путь к Qt (или стандартный `CMAKE_PREFIX_PATH`).
- Бинарник: `build/Source/Debug/Release/map_editor.exe` (windeployqt
  копирует Qt-рантайм рядом автоматически).
- Headless-тесты: `build/Source/Debug/Release/map_editor_tests.exe`,
  запускать из папки игры (содержит `RESOURCE/`): все проверки идут во
  временной копии `%TEMP%\map_editor_roundtrip`, папка игры не изменяется.

## Запуск и первый шаг

1. `File → Select Game Directory...` — папка игры (содержит `RESOURCE/`).
2. `File → Load World...` — мир из `RESOURCE/Worlds/*`; если в папке игры
   есть `Mods/<ModName>/RESOURCE/Worlds/`, миры модов попадают в тот же
   список в виде `<ModName> / <World>` и редактируются прямо в папке мода.

Все правки рельефа/цвета делаются кистями (панель Brush на тулбаре);
Undo `Ctrl+Z` / Redo `Ctrl+R`/`Ctrl+Y`. Правки, следующие друг за другом с
интервалом меньше **500 мс**, объединяются в одну транзакцию истории — один
`Ctrl+Z` откатывает всю серию (весь штрих кисти), пауза дольше 500 мс
начинает новую транзакцию. Мир сохраняется через `File → Save`
(`Ctrl+S`) — пишет `output.vmp`, палитры, `world.ini`, `hardness.bin`
(если был), `cache.tga`, `map.tga`.

## Справка

**Help → Map Editor Help...** (`F1`) — встроенное руководство (открывается
в отдельном окне, не мешает работе). Текст живёт отдельным файлом
`map_editor_help.md` рядом с исполняемым файлом редактора (копируется
сборкой из `Source/MapEditor/data/`); его можно править без пересборки.

## Возможности

### Миры
- **Просмотр**: 2D сверху (зум 1:1…fit, сетка с настраиваемым шагом,
  затемнение гео), наклонный 3D-вид (поворот/наклон/подъём/фокус,
  chunky/smooth; поворот также задаётся абсолютным спинбоксом градусов на
  тулбаре вида — 0–360°, циклический, синхронизирован с камерой в обе
  стороны), **камера как в игре** (View → Camera Like in Game —
  модель psi/theta/distance с игровым FOV `HardwareCameraFocus`, наводится
  на камеру первого игрока мира из `.spg`; View → Camera Like in Editor —
  возврат), миникарта с прямоугольником вида (в обоих режимах камеры рамка
  следует за реальным фрустумом). Миникарта показывает
  `map.tga`, а при несохранённых правках террейна (кисть, undo/redo, импорт
  картинки, правка палитры) досэмпливает картинку с живого террейна — не
  дожидаясь сохранения.
- **Кисти**: подъём/опускание/выравнивание (Geo/Dam режимы), абсолютная
  установка произвольной высоты за один штамп, такое же одно-штамповое
  «Level to Zeroplast» (сила кисти на него не влияет), пометки
  (гарь/very light dam),
  цвет (с учётом слоя клетки), пипетка; формы: круг/квадрат (заливка/контур),
  правильный многоугольник (заливка/контур; число вершин 3–20 и угол первой
  вершины 0–360° задаются спинбоксами на тулбаре кисти, радиус кисти —
  радиус описанной окружности), линия, **Scripted Brush** — тип кисти,
  выполняющий JavaScript (duktape) над дамбой: API подъёма/опускания/установки
  высоты, зеропласта, гари, very light dam и покраски ближайшим цветом
  Dam-палитры по явным координатам и радиусам, чтение высоты дамбы
  (getDamHeight) и цветов слоёв в клетке (getGeoColor/getDamColor → {r,g,b},
  индекс SurBuf через палитру слоя), запись цветов палитр
  (setGeoPalette/setDamPalette(index, {r,g,b}) — запись цветов палитр), окна сообщений
  showInfoMessageBox /
  showErrorMessageBox (позиция вне карты в геттерах — исключение); скрипт
  правится в отдельном
  окне (подсветка API, номера строк, проверка синтаксиса по OK, выбор формы
  превью), лимит 20 с на штамп, весь штамп — одна запись Undo; Dam-режим
  только. Тот же API доступен из **Tools → Run Script...** — окно выполнения
  скрипта (без настроек превью; кнопки Run/Cancel): один прогон по кнопке
  Run, `getCurrentPos()` — клетка под курсором, один шаг Undo, без
  Dam-only ограничения. Собственный тулбар **Sculpting** (разрыв тулбаров перед ним — своя
  строка): **Smooth**, **Flatten**, **Tricubic**, **Inflate**, **Deflate** и
  **Gaussian Blur** (Dam только) — двигают
  клетки под штампом на общую долю (спинбокс 0–1) пути к средней высоте / плоскости наименьших
  квадратов / бикубической интерполяции грубой решётки / смещению вдоль
  воксельных нормалей (пересечения при наращивании — по максимуму высоты,
  при сжатии — по минимуму) / свёртке с гауссовым ядром (радиус ядра —
  отдельным спинбоксом, строго меньше радиуса штампа; сэмплируются реальные
  соседние клетки, плоскости воспроизводятся точно); высоты правятся тем же тулзером Terra, что и Level to Height,
  цель считается по состоянию до штампа. Там же — **3D-кисти** (Dam только):
  **Cone / Pyramid / Truncated Cone / Truncated Pyramid / Half Torus /
  Half Ellipsoid** — штампуют твердое тело, основанием которого служит круг
  или правильный многоугольник радиуса кисти (превью в обоих видах рисует
  основание, у тора — с внутренним кольцом). Цель клетки — `Height +
  профиль·Shape Height` (профиль ∈ [0;1] — сечение тела); Raise подводит
  клетки к цели снизу, Lower — сверху (достигнутая высота не трогается,
  повторный штамп готовой формы — отказ без Undo), Set-to-Height берёт Height
  как базу основания и двигает в обе стороны, Shape Height = 0 в Lower/Set
  стирает форму до базы (дamba снимается). Настройки на тулбаре: спинбокс
  **Shape Height** (амплитуда), **Upper part X/Y** (смещение вершины, наклон
  оси), **Upper part radius** (верх усечённого конуса / внутренний радиус
  тора), **Upper part side** (сторона верха усечённой пирамиды) — каждое
  поле только у своих фигур, верх клампится строго внутрь основания; число
  сторон и угол вершин основания — общие спинбоксы 2D-полигона. Работают с
  Apply Above / Below Height, в Geo отказывают.
  Собственный тулбар **Model** (разрыв тулбаров — своя строка): импорт PLY
  (ascii/binary; модель — как ТВЁРДОЕ ТЕЛО: на колонку ячейки кладётся верх
  поверхности модели — грани сэмплятся барицентрикой, максимум wins, дырки —
  только где над колонкой нет поверхности вовсе; цвет — интерполяция
  вершинных цветов победившей грани; текстура из `comment`-строки
  сэмплится по UV; цвета квантуются в Dam-палитру тем же k-means, что Image
  Decal), кнопка **Use Model Brush** и режимы
  **Place / Add / Subtract** + спинбоксы **Height** (z-диапазон модели
  пропорционально на 0..Height) и **X/Y scale** (0..1). Превью — прямоугольник
  размещения. Place ставит дамбу на высоты модели и красит квантованные
  цвета (как Set-to-Height); Add поднимает покрытую среднюю на локальную
  высоту модели; Subtract опускает (ниже рельефа — дamba снимается).
  Dam-режим только, Geo отказывает.
  Картинка-маска (альфа 0 = не красить),
  **Image Decal** — картинка
  (PNG/TGA/BMP до 512 px) сводится к цветам Dam-палитры через k-means и
  штампуется на дамбу по индексам палитры. Для незаполненных форм (контур
  круга/квадрата/многоугольника, линия) есть **толщина штриха**: полоса
  растёт внутрь от внешнего края, поэтому широкий штрих не выходит за обычный
  отпечаток кисти.
  Радиус кисти — до 512 клеток (штамп до 1025×1025); ограничение — чисто
  редакторское, маски строятся аналитически и от таблиц Terra не зависят.
  Отдельный тулбар **Brush Modifiers** (разрыв тулбаров перед ним — своя
  строка; те же действия в Edit → Brush Modifiers): модификаторы
  **Apply Above Height** / **Apply Below Height** — пер-воксельное условие
  поверх любого типа кисти: эффект касается вокселя, только если высота дамбы
  этого вокселя строго выше / строго ниже порога **Gate Height** (спинбокс
  0–255 вокселей, доступен, пока активен модификатор; воксель ровно на пороге
  не редактируется). Dam-режим только: включение модификатора само
  переключает слой на Dam, в Geo условие игнорируется; штамп, где все воксели
  не проходят условие, отклоняется без записи в Undo; у скульптинга решение
  принимается по высоте до штампа.
- **Палитры**: редактирование Geo/Dam RGB (двойной клик), синхронизация
  `geoPal.xml` при сохранении.
- **Режим различий (.gmp)**: `.gmp` — механизм боевых карт менять рельеф для
  отдельных режимов («Сражение»/skirmish, «Выживание»/survival, сценарии),
  не трогая сам мир: различия лежат рядом с `.spg` и игра накладывает их при
  загрузке карты. Тоггл Difference Mode (View, `F2`) показывает
  мир с различиями и пишет правки кистей в `.gmp`-данные (формат игры) —
  при этом сам мир НЕ помечается изменённым; при выходе редактор предлагает
  сохранить данные различий в `.gmp`, а не сливать их в мир;
  File → Save Difference (.gmp) — рядом с `.spg` боевой карты, работает в
  любом состоянии тоггла; **File → Save всегда пишет базовый террейн мира —
  различия в мир не вливаются никогда**. Превью мира
  (`map.tga`/`cache.tga`, Export Top View для экрана выбора карты) генерируются
  всегда от базового террейна — игра их не накладывает с `.gmp`.
- **World Parameters** (`File → World Parameters...`): `hZeroPlast` (в живую),
  степени генерации (в `world.ini`, применяются после перезагрузки мира),
  сжатие `output.vmp` S2T0/S2T1 (конвертация сразу и при каждом сохранении),
  3DF-параметры гео-шума, цвет зеропласта (`Perimeter.ini [TD] Color
  ZeroLayer` — общая для игры).
- **Новый мир** (`File → New World...`): имя, шаблон (палитры/текстуры
  копируются из существующего мира), плоский рельеф на выбранной высоте
  гео-слоя или процедурная генерация (`buildWorld`), параметры карты.
  Созданный мир сразу загружается и сохраняется.
- **Изображения** (`File → Images`):
  - Import Image onto Map — раскраска `SurBuf` из PNG/JPG/BMP/TGA
    (RGB → ближайший индекс палитры слоя клетки; indexed TGA → индексы
    как есть); фильтры «красить гео/дамбу»; один шаг Undo;
  - Import up.tga — любая картинка → `up.tga` 512×512 24-бит;
  - Import leveledSurfaceTexture.tga — с валидацией (палитровый TGA,
    степень двойки, ≤ размера карты) и живой перезагрузкой;
  - Export Heightmap (8-бит серый TGA, `SGetAlt >> 5`) и Export Top View.

### Боевые карты (`.spg`)
- **Open Battle Map** (`File`): `RESOURCE/Battle/*.spg`, `RESOURCE/Worlds/*.spg`;
  мир из `worldName` загружается автоматически. Формат — XPrm-текст
  (`MissionDescriptionPrm` + `SavePrm`); файл воспроизводится байт-в-байт,
  если правки его не касаются (неизвестные узлы — контролы UI, триггеры —
  сохраняются как есть). `.gmp`/`.dat` игнорируются полностью.
- **Панель Battle Map** (клавиша B): игроки с координатами спавна, Go To,
  Move to View Centre (двигает фрейм + сквад + стабильную позицию + юнитов
  фрейма + камеру; z корректируется на разницу высот рельефа), Edit
  Properties (имя/тип/фракция/цвет/клан/сложность/гандикап + Location X/Y —
  прямой ввод координат спавна с той же коррекцией высоты по рельефу),
  New Battle Map; режим **Place Spawn** (кнопка на тулбаре Brush, `S`):
  клик по карте переносит спавн выбранного игрока в клетку без правки
  рельефа, с коррекцией высоты и одной записью undo (`Ctrl+Z`/`Ctrl+R`
  работают и с историей переездов спавнов; режим активен только при
  загруженной боевой карте)
  (шаблон + число игроков 1..8 + спавны по эллипсу + `zeroLayerHeight`
  из текущего мира).
- **Save / Save As**: в `RESOURCE/Battle` или `RESOURCE/Worlds`, с
  предупреждением о перезаписи. При сохранении (включая мастер New Battle
  Map) выполняется нормализация стартовой посадки фреймов:
  1. `restPlayersOnZeroLayer` — фрейм записывается в «посаженную» позу:
     `z = высота рельефа под фреймом + kFrameOriginGroundOffset (114.58 —
     расстояние начала координат модели FrameII от её низа; одинаково у
     всех штатных установленных карт независимо от фракции: PENTOLL
     254.58−140, XELA 234.624−120, COMPASS p3 291.58−177)`. Игра
     устанавливает фрейм ровно в записанной z (у тела фрейма gravity = 0),
     а шаблон COMPASS хранит ПОЗУ ВЗЛЁТА (рельеф + 114.58 + ~37 — тот самый
     `flying_height = 40` из RigidBodyPrm): установленный из неё фрейм
     висит в воздухе (баг EXTDEMO/MapDemo). Упакованные постройки во
     frameSlots едут с фреймом; сквад выше зеропласта опускается на него,
     ниже — не трогается;
  2. `setFramesInstalledForStart` — фреймы пишутся в состояние
     «установлен на старте» (`attached = true`, `powered = true`,
     `zeroLayerCounter` = уникальный положительный id). Шаблонное
     состояние семейства COMPASS (`attached = false`, счётчик 0) оставляет
     фрейм висеть в режиме ISOLATED, пока его не установит скрипт или
     игрок; у всех остальных штатных карт фреймы установлены, а ненулевой
     счётчик заставляет игру (`loadZeroLayer` → `placeZeroLayer` →
     `plotCircleZL`) предварительно рисовать диск зеропласта под фреймом —
     тот самый «зеропласт под фреймом на старте».
  Обе половины идемпотентны; z-половина на неприкосновенной карте
  сохраняется байт-в-байт.
- Оверлей спавнов рисуется в обоих видах: в 2D — цветные кольца без подписей
  (имена игроков не выводятся во вьюпорт, только в панели Battle Map), в 3D —
  цветные кружки (диски) цвета игрока, спроецированные на рельеф в точке
  спавна; положение обновляется при любом изменении спавна (Move to View
  Centre, New Battle Map, правки панели).
- **Предустановленные здания** (панель Buildings, вкладка у Battle Map):
  часть `nobodysBuildings` (список `SaveUnitBuildingData` в `SavePrm`) —
  здания фракций (43 типа: CORE, COMMANDER, все разрешённые постройки;
  исключены FRAME, SCUM_SPOT 1–4, BLACK_HOLE). На панели — кнопки
  разрешённых зданий с иконками, запечёнными из самих игровых M3D-моделей
  (до появления GPU-вьюпорта — текстовые подписи), угол поворота и HP
  выбранного/ставимого здания. Три инструмента: **Place** (клик ставит
  здание над зеропластом, `z = высота зеропласта + zOffset` из каталога;
  предпросмотр — контур зелёный/красный и сама модель под курсором,
  пересечение с другим зданием запрещает установку), **Select** (выбор
  здания, правка угла и HP через панель), **Delete** (клик удаляет).
  Загружаются/сохраняются из `.spg` (типизированные узлы XPrm в том же
  стиле: `unitID` уникален по документу, для COMMANDER и CORE — свои
  подтипы с дополнительными полями). В 2D-виде и на миникарте рисуются
  белыми точками (как радар игры), в 3D — настоящими M3D-моделями с
  игровыми текстурами и светом; выбранное здание подсвечивается оранжевым
  кольцом. Правки не входят в undo-историю рельефа (как переезды спавнов).

- **Скверна-гнёзда** (панель Scum Nests, вкладка у Battle Map): пары
  «курган SCUM_SPOT/2/3/4 (43..46) + невидимый спавнер FILTH_SPOT под
  ним» — по образу зданий (Place/Select/Delete, угол, HP, иконки из
  моделей). Курганы — в `nobodysBuildings`, спавнеры — в
  `SavePrm.filth.objects` с меткой `scum_spot_<id>`; параметры спавнера
  (тип скверны, число существ, сон/периоды, кем активируется, кого
  атакует) редактируются в панели для выбранного гнезда. Минимум 150
  единиц между курганами; z = zero layer + offset. При сохранении пишется
  `Scripts/Triggers/<мир>.scr` (цепочка START + активация/деактивация
  каждого спавнера по живости своего кургана — по образцу 03isoland) и
  регистрируется в TriggerChainNames каждого игрока рядом с mp-N.scr; без
  гнёзд файл и регистрации удаляются. В 3D курганы рисуются моделями
  filth_spot*.m3d, в 2D — белыми точками; на миникарте и в экспорте
  top-down не отображаются.

### Валидация (`Tools`)
- **Validate World**: обязательные файлы, размеры (степень двойки ≤ 16384),
  `hZeroPlast` 0..255, палитры (768 байт), `leveledSurfaceTexture.tga`,
  заголовок `hardness.bin`; **объёмный баланс** (T9.3): объём грунта выше
  плоскости зеропласта против объёма впадин, допуск в % от объёма впадин —
  при выходе предупреждение, что выравнивание потребует импорта/экспорта
  грунта.
- **Validate Battle Map**: мир существует, спавны в границах карты (с
  переходом к проблемному месту), имена игроков уникальны, камеры на
  каждого игрока, `playersShufflingIndices` покрывает всех.
- **Автофиксы**: нормализовать shuffling indices; выставить
  `zeroLayerHeight` из мира; перегенерировать `cache.tga`/`map.tga`.

## Форматы (кратко)

| Файл | Что редактор делает |
|---|---|
| `output.vmp` | S2T0 при сохранении; S2T1 — опция (конвертация тем же zlib-кодом, что игра) |
| `world.ini` | правки сохраняют формат/комментарии/неизвестные ключи байт-в-байт |
| `inGeo.act`/`inDam.act` | 768 байт RGB; плюс синхронизация `geoPal.xml` |
| `cache.tga`/`map.tga` | регенерируются при каждом сохранении (тот же растр, что вьюпорт) |
| `up.tga` | не читается игрой; редактор пишет 512×512 24-бит |
| `hardness.bin` | обновляется только если уже существовал |
| `*.spg` | XPrm-текст; байт-сохраняющие правки, `.gmp`/`.dat` не трогаются.
  Имена игроков хранятся в кодировке файла (Windows-1251 у русских карт,
  включая штатный COMPASS.spg — «Наместник»); `SpgFile` детектирует её при
  загрузке и транскодирует в UTF-8 на границе API, сохранение пишет имя
  обратно в той же кодировке (неизменённые файлы — байт-в-байт) |

## Ограничения

- Камера «как в игре» доступна только в GPU-пути 3D-вида (модель
  `terCameraType` + игровой FOV воспроизведены в `TerrainGpuView`); без
  GPU-рендера остаётся редакторская камера.
- Изменение степеней генерации (`GeoNet Power` и др.) у **загруженного**
  мира пишется в `world.ini` и применяется только после перезагрузки мира
  (буферы уже выделены под текущие размеры).
- `Minimal Square Power` в `world.ini` фактически игнорируется загрузчиком
  игры (квиры — `docs/context.md`); редактор сохраняет значение как есть.
- Цвет зеропласта — глобальная настройка игры (одна на все карты), хранится
  в `Perimeter.ini`, не в мире.
- Оверлеи: спавны — в обоих видах (2D: цветные кольца
  без подписей; 3D: цветные диски на рельефе в точке спавна, GPU-путь
  проецирует через реальную камеру, CPU-фолбэк — аффинный базис viewV2D);
  сетка — в обоих (в 3D плоскость зеропласта).
- Папки `mods/*` сканируются только для МИРОВ (`Mods/<Mod>/RESOURCE/Worlds`);
  боевые карты из модов не подхватываются.
- Валидация объёмов использует видимую поверхность (`SGetAlt`), дамба
  приоритетна.

## Приёмка в игре (T10.3, ручной чек-лист)

Планируемые проверки (не автоматизированы): мир открывается в бою (рельеф,
цвета, зеропласт, дамбы совпадают с редактором); новая боевая карта
запускается в «Сражении» (игроки на своих спавнах, камеры на месте, базы
целы); правка существующей карты не ломает базы/камеры/скрипты;
сжатый S2T1 мир грузится игрой.
