# Анализ производительности кисти в 3D-режиме

## Проблема

Рисование кистью (круг или квадрат) в Oblique (3D) режиме при движении мыши по экрану работает медленно — наблюдается задержка, подтормаживание.

## Код, выполняемый при каждом движении мыши

При нажатой левой кнопке мыши в режиме рисования кистью в 3D-виде на каждое событие `mouseMoveEvent` выполняется следующий путь:

```
ViewportWidget::mouseMoveEvent()
  └─ cellAtWidgetPos(pos)          // [1] поиск ячейки под курсором
       └─ View3DRenderer::pickGroundCell(cx, cy, col, row, mx, my)
            └─ for (int d = -yside-200; d < yside; ++d)  // до 680 итераций
                 └─ bilinear height sampling + trig + sqrt
  └─ applyBrushStampHere(cell)     // [2] нанесение штампа
       └─ brush->applyStamp(cx, cy)
            └─ BrushMasks::byShape()  // аллокация нового вектора, O(radius²) ячеек
            └─ applyMask()
                 └─ recordUndoArea()    // копия области для undo
                 └─ applyEffectToCell() // для каждой ячейки штампа
                 └─ vMap.recalcArea2Grid()
                 └─ vMap.regRender()
  └─ viewport.update()             // [3] полный перерисовка 3D
       └─ paintEvent()
            └─ draw3DRaster()
                 └─ view3DRenderer::render(cx, cy)
                      └─ viewV2D() или renderSmooth()  // полный рендер буфера
```

## Измеренные затраты на каждый этап

### [1] `pickGroundCell()` — обратная проекция

Каждый вызов выполняет линейный проход по всем строкам фрустума от `d = -yside-200` до `d < yside`:

- Для буфера 640×480: `yside = 240`, цикл выполняется **до 680 итераций**
- На каждую итерацию: `sqrt()`, `tan()`, `cos()`, `sin()`, `round()`, билинейная интерполяция высот (4 чтения буфера + 3 умножения)
- **Стоимость**: ~680 × тяжёлая математика на каждое движение мыши

### [2] `applyStamp()` — нанесение штампа

- `BrushMasks::byShape()` — **аллоцирует новый `std::vector`** на каждый вызов
- Для радиуса 10: 21×21 = 441 ячейка (аллокация + заполнение)
- `recordUndoArea()` — копия области для undo
- `applyEffectToCell()` — для каждой ячейки штампа
- `recalcArea2Grid()` + `regRender()` — пересчёт сетки на каждый штамп

### [3] `draw3DRaster()` — полный 3D-рендер

Каждый `update()` запускает полную перерисовку 3D-буфера:

- `viewV2D()` или `renderSmooth()` — полный проход по всему буферу
- Для буфера 640×640: **~537 600 итераций** на каждый рендер
- Каждая итерация: арифметика, выборка цветов из мип-пирамиды (smooth mode)
- **Стоимость**: ~537K итераций на каждый `update()`

## Итоговая оценка затрат

При движении мыши со скоростью 125 Hz (типичный polling rate игровой мыши):

| Этап | Стоимость за вызов | Вызовов/сек | Затраты/сек |
|------|-------------------|-------------|-------------|
| `pickGroundCell()` | ~680 итераций | 125 | ~85 000 итераций |
| `applyStamp()` | ~441 ячейка (радиус 10) | 125 | ~55 125 ячеек |
| **Полный 3D-рендер** | **~537 600 итераций** | **125** | **~67 200 000 итераций** |

**Главный узкий горлышко — полный 3D-рендер на каждый `update()`**.

## Рекомендации по оптимизации

### 1. Кэширование `pickGroundCell()` — высокий приоритет

`pickGroundCell()` вызывается на каждое движение мыши, но результаты для одного и того же столбца `col` не меняются, пока камера не двигается.

**Предложение**: Предвычислить таблицу поиска `pick_table[col][row] = (mapX, mapY)` при каждом изменении камеры, затем на движение мыши делать O(1) lookup вместо 680-итерационного прохода.

```cpp
// В View3DRenderer:
struct PickCell { int mapX; int mapY; };
std::vector<PickCell> pickTable_;  // размер: width_ * height_

void rebuildPickTable(int cx, int cy);
PickCell pickFromTable(int col, int row) const;
```

### 2. Батчинг `update()` — высокий приоритет

`update()` вызывается на каждый штамп, что запускает полный 3D-рендер. Это избыточно — можно отложить перерисовку до конца текущего кадра.

**Предложение**: Использовать `QTimer::singleShot(0, this, &QWidget::update)` вместо прямого `update()`, чтобы Qt объединил несколько вызовов в один `paintEvent`:

```cpp
// В applyBrushStampHere:
if (changed) {
    emit viewport.worldEdited();
    // Отложенный update — Qt объединит несколько вызовов
    QTimer::singleShot(0, &viewport, [&viewport]() { viewport.update(); });
}
```

### 3. Отложенная перерисовка 3D — средний приоритет

В Oblique-режиме 3D-рендер выполняется на каждый `paintEvent`, даже если камера не изменилась.

**Предложение**: Перерисовывать 3D-буфер только при изменении камеры или при явном запросе (после штампа). В обычном paintEvent использовать кэшированный буфер:

```cpp
bool needs3DRedraw_ = true;

void mark3DDirty() { needs3DRedraw_ = true; }

void paintEvent(QPaintEvent*) {
    if (viewMode_ == ViewMode::Oblique) {
        if (needs3DRedraw_) {
            draw3DRaster(painter);
            needs3DRedraw_ = false;
        } else {
            drawCached3D(painter);  // рисовать кэш без перерендера
        }
    }
}
```

### 4. Предвычисление масок кисти — низкий приоритет

`BrushMasks::byShape()` аллоцирует новый вектор на каждый штамп.

**Предложение**: Предвычислить и закэшировать маски для стандартных радиусов:

```cpp
// В BrushMasks:
static std::unordered_map<int, BrushMask> cachedMasks_;
static BrushMask getOrCreate(int shape, int radius);
```

## Оценка эффекта от оптимизаций

| Оптимизация | Ожидаемый эффект | Сложность |
|-------------|-----------------|-----------|
| Кэширование `pickGroundCell()` | ×3-5 быстрее выборка ячейки | Низкая |
| Батчинг `update()` | ×2-4 быстрее отклик | Низкая |
| Отложенная 3D-перерисовка | ×5-10 быстрее отклик | Средняя |
| Предвычисление масок | Небольшой выигрыш | Низкая |

**Наибольший эффект даст комбинация батчинга `update()` и отложенной 3D-перерисовки** — это устранит главный узкий горлышко (полный 3D-рендер на каждое движение мыши).

## Временные рамки

- Батчинг `update()`: 10-15 минут реализации
- Отложенная 3D-перерисовка: 30-45 минут реализации
- Кэширование `pickGroundCell()`: 1-2 часа (требует аккуратной синхронизации с камерой)

## Статус реализации

**Реализована отложенная 3D-перерисовка (п.3):** в `ViewportWidget` добавлен флаг
`needs3DRedraw_` — полный 3D-рендер (`viewV2D`/`renderSmooth`) выполняется только
при изменении камеры, центра взгляда, стиля отрисовки, размера окна, штампе кисти
или undo/redo. Обычное движение мыши с превью кисти теперь делает только blit
закэшированного RGB565-кадра (`blit3DFrame()`) + отрисовку кольца превью и HUD.
Это устраняет главное узкое горлышко: ~537K итераций рендера на каждое движение
мыши заменены на один проход по буферу только при реальном изменении сцены.

**Не реализовано (по результатам оценки):**

- Полная таблица `pickGroundCell()` (п.1) — отброшена: предвычисление таблицы для
  всех пикселей окна (640×640) дороже, чем одиночный `pickGroundCell()` с ранним
  выходом (первые строки фрустума дают попадание за десятки итераций).
- Батчинг `update()` (п.2) — Qt уже объединяет несколько `update()` до одного
  `paintEvent` в рамках цикла событий, дополнительная отложенная отрисовка через
  `QTimer::singleShot` эффекта не даёт.
- Кэш масок кисти (п.4) — не в профилированном узком горлышке, оставлено на будущее.
